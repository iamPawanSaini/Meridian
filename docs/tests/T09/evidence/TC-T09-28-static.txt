  /**
   * Runs rejection cases and accept cases of one bundle.
   *
   * @param string $bundle
   *   The bundle.
   * @param array<string, array{0: array<string, mixed>, 1: list<array{0: string, 1: string}>}> $cases
   *   Cases by label: field changes and the expected violations.
   */
  protected function runCases(string $bundle, array $cases): void {
    foreach ($cases as $label => [$changes, $expected]) {
      $this->assertViolations($this->record($bundle, $changes), $expected, $bundle . ': ' . $label);
    }
  }

55:## Violation contract (T10)
56-
57-`$entity->validate()` returns violations with a raw `getPropertyPath()` and `getCode()`.
58-`ViolationContractTest` pins these raw values. T10 maps them to JSON pointers, so it must apply
59-the normalisation below. The other Kernel tests apply the same normalisation.
60-
61-| Source | Raw path | Code |
62-|---|---|---|
63-| Meridian rule on a single-value field (`MeridianPattern`, `MeridianJsonDocument`, `MeridianDecimalScale`, `MeridianUniqueInBundle`, ...) | `field_symbol` | `meridian.*` |
64-| Meridian rule on one value of a multi-value field (`field_rule_hits`) | `field_rule_hits.0` (the delta) | `meridian.pattern` |
65-| Meridian rule on the whole multi-value field (`field_modes`) | `field_modes` | `meridian.duplicate_value` |
66-| Cross-field and external ID rules | `field_external_id`, `field_buy_count`, ... | `meridian.<bundle>.<rule>`, `meridian.external_id_mismatch` |
67-| Core range, length, scale of a value | `field_score.0.value` | core UUID code (`Range::TOO_HIGH_ERROR`, `Length::TOO_LONG_ERROR`) |
68-| Core allowed values | `field_mode.0` | `Choice::NO_SUCH_CHOICE_ERROR` |
69-| Core required | `field_score` | `NotNull::IS_NULL_ERROR` |
70-| Reference to a missing or wrong-bundle node | `field_run.0.target_id` | empty string `''` |
71-| Malformed date | `field_trade_date.0` and `field_trade_date.0.value` (two violations) | empty string `''` |
72-| Base field (title) | `title.0.value` | core code |
73-
74-Normalisation T10 applies: remove a trailing `.value` or `.target_id`; for a field other than
75-`field_rule_hits` and `field_modes` also remove a trailing `.0`; keep the delta for those two
76-multi-value fields. The result is the field machine name (strip `field_` for the payload name),
77-except `field_rule_hits.N` and `field_modes.N`, which point at item N. Two violations can have the
78-same path (a malformed date). A violation with an empty code comes from core and T10 should map
79-it by path and message, not by code.
