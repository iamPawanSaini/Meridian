# apps/drupal

Drupal 11 Composer root for Meridian (headless content backend and admin). It is also the root
of the subtree split that deploys to Pantheon (ADR-0004, T07), so everything Pantheon needs lives
here and nothing outside this folder is required to build it.

## Layout

| Path | Tracked | Purpose |
|---|---|---|
| `composer.json`, `composer.lock` | yes | Dependencies. Hand-written, modelled on the Pantheon upstream (see "Upstream reference") |
| `pantheon.yml` | yes | Pantheon settings: PHP and database version, `build_step: true` (Integrated Composer) |
| `web/` | partly | Docroot. Only `web/sites/default/settings.php` and `web/modules/custom/` are ours |
| `web/sites/default/settings.php` | yes | Include order and `config_sync_directory`. No secrets |
| `config/sync/` | yes | Exported configuration, `minimal` profile baseline |
| `web/modules/custom/` | yes | Custom modules `meridian_ingest`, `meridian_core` (T09, T10) |
| `phpcs.xml.dist`, `phpstan.neon.dist` | yes | PHP style and static analysis (T04a) |
| `vendor/`, `web/core/`, contrib, scaffold files | no | Generated by `composer install`. Pantheon regenerates them |
| `private/` | no | Private files, ignored (set up in T10) |

## Local use

Everything runs through DDEV. The host PHP is not used.

```bash
ddev start             # starts the project; the post-start hook runs composer install
ddev drupal-install    # site install plus config import from config/sync
ddev drush uli         # one-time admin login link
```

The full procedure is `docs/runbooks/local-setup.md`.

## Tests

PHPUnit has two suites in `phpunit.xml.dist`: `unit` and `kernel`, both over
`web/modules/custom/*/tests/src`. T09 adds no Functional tests. Run them in DDEV:

```bash
ddev exec -d /var/www/html/apps/drupal vendor/bin/phpunit --testsuite unit
ddev exec -d /var/www/html/apps/drupal vendor/bin/phpunit --testsuite kernel
```

Kernel tests need a database. `SIMPLETEST_DB` is the PHPUnit variable that holds its URL, in the
form `mysql://user:password@host/database`. Kernel tests create their own prefixed tables and
drop them afterwards. DDEV sets it to the project database in `.ddev/config.yaml`
(`mysql://db:db@db/db`, the DDEV default credentials, not a secret). CI sets it for its MariaDB
service container. The URL is never kept in `phpunit.xml.dist`, and SQLite is not used.
A Kernel test class takes about ten seconds per test method, so the full Kernel suite runs for
several minutes.

`ddev quality` runs the suites with coverage and the 70% gate on `web/modules/custom/meridian_`.
In CI the coverage driver is pcov. The DDEV web image has no pcov package for PHP 8.3, so the
DDEV run loads Xdebug in coverage mode for that one command (`scripts/README.md`).

`meridian_core` is documented in `web/modules/custom/meridian_core/README.md`.

## Config workflow

Configuration lives in `config/sync/` and is the source of truth.

1. Change configuration in the admin UI or with Drush.
2. `ddev drush config:export -y` (`ddev drush cex -y`).
3. Review the diff of `apps/drupal/config/sync/` and commit it.
4. To check that the site equals the repository: `ddev drush config:status` must say
   "No differences".

`ddev drupal-install --force` drops the local database and reinstalls from `config/sync/`. It
keeps the committed site UUID.

Do not apply Pantheon dashboard upstream updates. Code arrives by subtree push only (ADR-0004).

## Upstream reference

`composer.json` follows the structure of `pantheon-upstreams/drupal-composer-managed`
(repository `main`, commit `f39249843ad2772f6789033072340c7de62d99eb`, pushed 2026-10-20, read
2026-11-01). That template still pins Drupal 9 constraints and ships an `upstream-configuration`
path repository and Composer scripts. We copy the layout only (installer paths, scaffold
`allowed-packages`, `web-root`) and use Drupal 11 constraints. We leave out
`upstream-configuration` because we deploy by subtree push, not by upstream updates.

## Composer plugins

`config.allow-plugins` lists each decision. `symfony/runtime` is `true`: Drupal 11.4 `index.php`
requires `vendor/autoload_runtime.php`, which that plugin generates (with it off, every page
fatals; found by the live login check). `php-http/discovery` and `tbachert/spi` are `false`: Drupal
does not need their plugin hooks. Add new plugins only on purpose and never use `"*": true`.

## Ignore rules

`.gitignore` in this folder is tracked on purpose. Only `apps/drupal` is split and pushed to
Pantheon, so the root `.gitignore` does not travel with it, and the Integrated Composer build fails
on untracked scaffold output without this file (DEF-010). Keep it in step with the `apps/drupal`
block of the root `.gitignore`; when a Composer change adds a scaffold file, add it to both.
